# RoleSpec OS v2.1.1

RoleSpec OS v2.1.1 refreshes the visual identity with the supplied brand kit, adds a
release-channel selector to desktop updates, and keeps the signed update checks from
[v2.1.0](v2.1.0.md).

## New brand

- The app and installer now use the supplied RoleSpec OS brand mark: the filled geometric
  monogram on a rounded blue tile with the ice accent.
- The same mark replaces the old hand-drawn monogram in the window icon, taskbar icon,
  Start-menu entry, installer header and sidebar images, favicon, PWA icon and the in-app
  sidebar and marketing pages.
- `public/brand/` ships the official light and dark wordmarks plus five icon colourways:
  `brand` (blue tile), `ink` (dark tile), `ice` (light blue tile), `mono` (single colour)
  and `on-dark` (transparent, for dark surfaces).
- The in-app `LogoMark` takes a `variant` prop, so a surface can use the colourway that
  fits without redrawing the mark.
- Regenerate the desktop icon set after a design change with `npm run desktop:icons`.

## Release channels

- **Settings → Preferences → Desktop updates** now has a stable/beta selector.
- Stable reads `releases/latest/download/latest.json`. Beta reads the rolling `beta`
  release at `releases/download/beta/latest-beta.json`.
- Both manifests are signed by the same updater key, and the downloaded artifact is still
  verified against the public key compiled into the app. Switching channel does not weaken
  signature verification.
- The channel is stored separately from the automatic-check preference, so turning checks
  off does not move a beta user back to stable, and choosing beta does not re-enable
  automatic checks.
- A stable release also refreshes the beta channel pointer, so beta users on an older
  prerelease are offered the newer stable build. Switching back to stable does not
  downgrade an installed beta build; it stops offering prereleases until a newer stable
  exists.
- **Check for updates** re-reads the selected channel and applies it immediately.

## Installer and updater

- Release tags are classified automatically: a stable tag such as `v2.1.1` publishes a
  normal release and `latest.json`; a prerelease tag such as `v2.2.0-beta.1` publishes a
  GitHub prerelease and `latest-beta.json`. Both refresh the rolling `beta` release.
- The Windows installer remains unsigned. Windows may show SmartScreen or an
  unknown-publisher warning; see
  [DESKTOP.md](../DESKTOP.md#windows-trust-and-smartscreen).
- The v2.0.2 → v2.1.0 in-app update path was exercised on Windows 11 x64, including the
  native prompt, signature verification, the version change and the updated settings page.
  v2.1.1 uses the same updater and does not change the install identity or data location.

## Updating

Automatic checks remain on by default. An installed v2.1.0 can accept the signed update to
2.1.1. Older copies without updater metadata must install a new setup file manually.

Download `RoleSpec_2.1.1_x64-setup.exe` and compare its SHA-256 against `SHA256SUMS.txt`.
The install identity (`RoleSpec`, `com.rolespec.desktop`) and the
`%LOCALAPPDATA%\RoleSpecData` data location are unchanged, so an upgrade preserves the
workspace.
